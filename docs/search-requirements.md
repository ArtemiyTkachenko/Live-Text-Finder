# Shared live search requirements — CS-001 / CS-002 / CS-003

## Implemented contract

One labeled, single-line manual query is restored from the last completed Android save, including explicit clear. A named saved list can instead activate several independent terms/phrases simultaneously without discarding the manual query. Typing/editing/clearing switches to manual mode and derives results immediately from the latest eligible `OcrUiState`; no submit or OCR restart is required. Presentation retains individual missing matched occurrences briefly, including when other matches remain. Each occurrence keeps its own exact source snapshot, projection and element provenance; latest OCR diagnostics and recognized count remain authoritative and separate. New observations replace their geometry immediately. Missing occurrences expire at the earlier of 300ms after their first missing accepted result or 1,500ms after their last actual observation; repeated misses and recomposition cannot extend this deadline. Query edits discard held entries and recompute against the latest eligible snapshot. Association is conservative, local and one-to-one; current geometry wins over overlapping or clearly displaced old entries. No synthetic mixed OCR snapshot, coordinate smoothing or image-based motion tracking is promised.

The root layout is one inset-aware Column: search input receives priority, preview takes the remaining height, and secondary diagnostics use a fixed scrolling viewport when space permits. Keyboard/compact/large-font layouts hide the camera preview and secondary content so the field stays visible. The user chose this behavior after device testing; shrinking the preview is deferred. Android explicitly requests adjustResize; Compose owns IME padding once. Android permission/settings content and action remain scrollable together in the preview viewport. Camera session/resource ownership is unchanged. Actual keyboard, landscape and large-font behavior still require device observation.

- Normalize query and each element by trimming leading/trailing Kotlin `Char.isWhitespace` characters and collapsing internal runs to one space. Preserve punctuation, hyphens, accents and all other characters.
- Join each line's nonempty normalized elements with one space in existing order. Search lines independently; never cross line boundaries. Aggregate `line.text`/`snapshot.text` remain diagnostic only and do not create extra occurrences.
- Use literal `indexOf(..., ignoreCase = true)` comparisons, without lowercasing/expanding the searched content. This is deterministic common Kotlin character-case behavior, not universal locale-aware equivalence, accent folding or Unicode normalization. For example, `CAFÉ` matches `Café`; `cafe` does not. `STRASSE` does not match `Straße`; `i` matches the simple case variant `İ`. Composed/decomposed accents are not equated. No regex/fuzzy/stemming modes exist.
- Find left-to-right non-overlapping occurrences. `banana` / `ana` counts one; `foofoo` / `foo` counts two in the same element. `[AB-123, part]` / `ab-1` selects element 0; `123 part` selects elements 0 and 1.
- Each occurrence records normalized-line character range, original line index and original participating element indices. Empty elements are skipped without renumbering source identity. Join separators do not select elements. Result retains the original eligible snapshot, including its frame metadata and untouched geometry. Missing element geometry does not discard a textual occurrence. Counts are occurrences, not drawable boxes. The matcher infers no preview/character-box coordinates; a separate validated projection maps full recognized elements.
- Search is eligible only in `Scanning` or `TextRecognized` with a current snapshot. All other statuses discard retained snapshots for search. A new or empty snapshot replaces prior results, and status/query changes recompute them. An empty/whitespace query gives no matches and an invitation when a current snapshot is available.
- Active nonempty results say `Recognized matches: N`; zero results say `No matches in recognized text`. Expired Scanning state says `Waiting for fresh recognized text`; inactive/unavailable current search says `Search paused · see camera status`; camera/OCR status and recovery keep precedence. This never implies absence from the physical object or a safety guarantee.

Standard-library references checked 2026-10-25: [Kotlin indexOf](https://kotlinlang.org/api/core/kotlin-stdlib/kotlin.text/index-of.html), [Kotlin isWhitespace](https://kotlinlang.org/api/core/kotlin-stdlib/kotlin.text/is-whitespace.html).

## Acceptance and limits

Thirteen common host-executed tests cover empty query; identifiers/case; literal punctuation/hyphens/accents and nonexpanding comparisons; whitespace and original element indices; within-line phrases; forbidden cross-line phrases/empty lines; repeated non-overlap; duplicate lines; missing geometry; diagnostic text mismatch; query/snapshot replacement; and every status's eligibility. Assertions retain frame and element provenance, not just result existence. Existing lifetime/rotation tests remain intact. See [validation](validation.md) for actual results.

## Element outlines and actual mapping (CS-002)

Outline each distinct original `(lineIndex, elementIndex)` participating in current matches once. Repeated occurrences in one element count separately but draw once. Within-line phrases can outline several elements; partial matches outline whole OCR elements, never claimed character boxes. Prefer four ordered convex nondegenerate OCR corners; otherwise use a valid positive bounds rectangle. Missing/unusable geometry affects drawable-element count only. Fully off-preview polygons are omitted; partly visible polygons keep their original vertices and are clipped by Canvas. The selected outline colour (Yellow by default) uses a black under-stroke to retain readable text. No editor or animation mode is included.

Android supplies the actual `PreviewView.sensorToViewTransform`, while the frame's copied `sensorToBufferMatrix` supplies analysis provenance. Matrices use Android's nine-value row-major representation acting on column vectors, rightmost mapping first:

`viewPoint = sensorToView × inverse(sensorToBuffer) × inverse(fullBufferRotation) × uprightOcrPoint`.

After CS-003 Android result admission, common OCR coordinates are the full input buffer rotated clockwise in image coordinates (x right, y down), translated to positive upright coordinates. For raw `(x,y)` and full raw width W/height H, the rotation is 0° `(x,y)`, 90° `(H-y,x)`, 180° `(W-x,H-y)`, 270° `(y,W-x)`. There is no crop-origin subtraction from OCR points. The frame crop is validated; the actual target matrix already encodes native preview crop/scale/rotation. No upright-dimension stretch, guessed preview aspect, added rear mirror or dp conversion is used. Native PreviewView and overlay share local origin/size, so screen insets/parent offsets are not added again. Stroke widths alone use dp-to-pixel conversion. Exact native/overlay pixel-size mismatch suppresses drawing. Canvas also checks current query/source/size at draw time so a state or layout change between composition and drawing suppresses the previously composed outlines.

Require positive frame/view dimensions, quarter rotation, nonempty in-range crop, nine finite matrix values, invertible sensor/target transforms, finite output and usable geometry. CameraX mapping is affine; unexpected perspective is conservatively suppressed, not treated as identity. Degenerate/null/nonfinite/singular mapping never draws speculative outlines. When recognized matches exist but mapping is unavailable/invalid, show `Highlights waiting for preview` alongside recognized occurrence count. Ready mapping reports outlined-element count separately; missing/clipped geometry never changes matching semantics.

Every accepted result/projection belongs to one exact snapshot/frame, camera session and preview generation. Layout/size/target-matrix/rotation changes remove prior projection immediately and reject pending older-generation callbacks; only a fresh result for the current generation restores it. Current recognized counts may remain until receipt expiry while mapping is unavailable. Query-only edits reuse the exact current frame projection without waiting for OCR. Stream IDLE, lifecycle stop, nonmeasured/unattached view, permission/error or disposal clears current geometry/results as appropriate. Retired sessions and duplicate/out-of-order frame timestamps are rejected; timestamps order only within a session. A new retry owns a new PreviewView and session, preserving camera resource ownership.

The short presentation hold clears immediately on missing/current-invalid projection, geometry generation or session change, query edit/clear, inactive/error/permission state, or receipt expiry. A cancellable UI timer expires each held occurrence even without another OCR callback. Draw-time guards reject expired groups and a composed presentation superseded by a newer tracker observation. Physical scene motion is not detected by this policy; retained outlines can briefly lag, bounded by each missing occurrence's deadline and source freshness.

A reversible **1,500ms result-receipt age** limit clears snapshot, projection and live recognized count when OCR stalls. Android main-thread monotonic receipt time is separate from sensor timestamps; one reusable cancellable session-owned runnable targets the latest deadline. An older scheduled expiry consults the current receipt and cannot clear a newer result. Fresh eligible results restore current state. This is neither a performance target nor motion tracking.

## Pinned bundled result boundary — CS-003

`com.google.mlkit:text-recognition:16.0.1` includes local Latin ModuleDescriptor version10000; Latin options therefore select the thick/bundled branch. Resolved common19.1.0 `internal.zzp` selects `internal.zzd`, whose thick branch loads `BundledTextRecognizerCreator` → bundled-common17.0.0 `pipeline.zbi`. That bridge passes full YUV planes/width/height/recognition rotation to native inference. For returned line/element records it constructs bounds by applying `ImageUtils.getUprightRotationMatrix` to the point-envelope, but passes the separate point list unchanged. This difference is independent of unknown native pixel accuracy.

## Android freeze/resume — next bounded increment

Freeze requests one next analyzed frame, pairing its copied full-buffer pixels with that same frame's OCR snapshot. It is not a preview screenshot. While capture is pending, show cancellation; a five-second deadline invalidates late results. Freeze preserves up to one 4,000,000-pixel ARGB image in memory, with no per-frame image cache or disk persistence. Reject oversized or failed captures visibly.

Frozen display rotates the captured buffer once, centers it with aspect-preserving Fit and uses the same upright-to-viewport transform for outlines. Match the frozen snapshot on manual-query/list changes; label counts as frozen and apply no live freshness expiry or dropout retention. Preserve frozen pixels while keyboard/compact/list-manager visibility hides their renderer. Resume, lifecycle stop/background and Activity recreation discard captured data; resume starts a fresh live session. Android owns pixels and proxy/thread lifetimes; shared code owns immutable mode/snapshot/search behavior. No image import/export, iOS OCR, preview shrinking or APK generation.
